# LIGHT ONE 심사 리스크 검토와 실행 게이트

> 기준일: 2026-07-10. 이 문서는 현재 공개 저장소의 문서와 구현 상태를 바탕으로 한 내부 심사 대응 기준이다. 시장성, 매출, 정확도, 법률 적합성을 이미 검증했다는 주장이 아니다.

## 1. 냉정한 판단

현재 LIGHT ONE은 **조건부 진행(conditional go)** 단계다. 공공 지원사업 심사에서는 문제 정의, 비의료 경계, 파일럿 설계가 강점이 될 수 있다. 반면 투자 심사에서는 반복 가능한 유료 수요, 실제 사용 빈도, 데이터 운영 준비도, 기술 실행 안정성의 증거가 아직 부족하다.

따라서 지금의 목표는 기능을 넓히는 것이 아니라, **프리미엄 PT센터의 상담·재등록 업무에서 시간이 절약되고 설명 품질이 높아진다는 유료 검증 가능성**을 증명하는 것이다. 임상 정확도, AI 모델 우수성, 대규모 시장 점유율은 현재 단계의 주장이나 개발 목표가 아니다.

## 2. 심사위원이 보는 핵심 리스크

| 관점 | 리스크 | 현재 판단 | 보완 원칙 | 다음 증거 |
|---|---|---|---|---|
| 공공기관 | 의료기기·건강관리 서비스로 오인될 가능성 | 높음 | 진단·치료·처방·위험예측을 기능과 문구에서 제외하고, 모든 결과를 트레이너 검토 초안으로 제한 | 금지 표현 점검표, 라우팅 사유, 트레이너 승인 이력 |
| 투자자 | 고객의 실제 지불의사와 구매자가 불명확함 | 높음 | 첫 구매자를 프리미엄 PT센터의 대표·센터장으로 좁히고, 트레이너는 핵심 사용자로 분리 | 최근 문제 사례, 파일럿 약속, 유료 PoC 조건 또는 결제 의사 |
| 대기업 심사 | 단순 기록/리포트 기능은 쉽게 복제될 수 있음 | 높음 | 운동 기록 자체가 아니라 상담 준비-검토-피드백-재등록 설명의 현장 워크플로에 집중 | 반복 사용된 리포트, 재등록 상담 활용 사례, 운영 프로토콜 |
| 공통 | 입력 부담이 가치보다 크면 현장에서 이탈 | 높음 | 초기 필수 입력을 세션 기록, RPE, 컨디션/불편 반응, 트레이너 피드백으로 최소화 | 회원·트레이너별 입력 시간, 누락률, 주간 재사용률 |
| 공통 | 실제 건강·신체 이미지 데이터의 개인정보·민감정보 관리 부담 | 높음 | 공개 저장소는 합성 데이터만 사용하고, 파일럿 전 동의·권한·보관·삭제 절차를 구현·검수 | 데이터 목록, 동의 이력, 역할 권한, 삭제 요청 처리 기록 |
| 투자자/기술 심사 | QS·라우팅 임계값과 모델 정확도를 과장할 위험 | 중간~높음 | MVP는 규칙 기반 운영 큐이며, 의료 안전성·효과를 판단하지 않는다고 명시 | 경계값 테스트, 오분류 회고, 트레이너 수정 기록 |
| 대기업 심사 | 코드·migration·CI 안정성이 약하면 현장 PoC를 맡기기 어려움 | 높음 | 실제 데이터를 받기 전에 migration 단일화, 핵심 테스트, 배포 보안 점검을 통과 | `manage.py check`, migration 검증, 핵심 흐름 테스트, `check --deploy` |
| Hugging Face/AI | 데이터가 없는 상태에서 모델 학습·외부 업로드를 시작하면 규제·비용·평판 리스크가 커짐 | 높음 | MVP에는 학습·추론 호스팅·민감 데이터 업로드를 포함하지 않는다 | 합성 데이터만 쓰는 별도 실험 승인과 데이터 거버넌스 검토 |

## 3. 리스크를 줄이는 제품 결정

### 3.1 최초 고객과 문제를 하나로 고정

- **최초 구매자:** 프리미엄 PT센터의 대표 또는 센터장
- **최초 사용자:** 회원을 담당하는 트레이너
- **최초 사용 장면:** 재등록·중간 상담 전, 흩어진 기록을 검토하고 회원에게 변화와 다음 행동을 설명하는 순간
- **초기 가치 가설:** 자료 정리 시간과 상담 준비의 불확실성을 줄이고, 트레이너별 피드백 품질을 일정하게 만든다

필라테스, 교정운동, 일반 헬스장, B2C 앱, 병원·재활기관은 인터뷰 대상일 수는 있으나, MVP의 구매자·기능 요구를 결정하는 기준으로 사용하지 않는다.

### 3.2 리스크 조정 MVP

아래 기능은 하나의 상담 흐름을 완성하기 위한 P0 범위다.

1. 회원별 동의 상태와 역할별 접근 제어
2. 운동 수행, RPE, 컨디션, 불편 반응의 최소 입력
3. `AUTO`/`REVIEW`/`BLOCK`의 **운영상 검토 사유** 표시
4. 트레이너의 피드백 작성, 수정, 승인 이력
5. 트레이너 승인 후에만 공유 가능한 비의료 상담 리포트
6. 입력 시간·누락·리포트 수정 횟수를 남기는 파일럿 측정

다음 기능은 검증을 흐리거나 리스크를 높이므로 P0에서 제외한다.

- Samsung Health, 인바디 장비, 기타 외부 API 자동 연동
- 자세 추정 정확도 경쟁 또는 원본 사진·영상의 장기 보관
- AI 자동 처방, 통증 원인 추정, 질병·부상 위험 예측
- Hugging Face 모델 학습, 실사용 건강 데이터 업로드, 외부 추론 API 운영
- 다중 업종 맞춤 기능과 교육·인증·프랜차이즈 확장

## 4. 단계별 통과 조건

아래 수치는 현재 성과가 아니라, 다음 단계로 자원을 투입하기 위한 내부 검증 기준이다. 기준을 충족하지 못하면 기능을 추가하기보다 원인을 기록하고 가설을 수정한다.

| 게이트 | 통과에 필요한 증거 | 통과 전 금지 |
|---|---|---|
| G0. 파일럿 준비 | 비의료 문구 검수, 합성 데이터 데모, 역할 권한, 동의·보관·삭제 절차, migration/핵심 테스트의 재현 가능한 통과 | 실제 회원 데이터·사진 수집 |
| G1. 문제 강도 | 초기 구매자/사용자 대상 12건 이상 인터뷰, 그중 대표·센터장 4건 이상, 반복되는 최근 문제 사례와 현재 대체 방식 기록 | 인터뷰 반응을 traction이나 계약으로 표현 |
| G2. 사용성 | 1~3개 센터의 제한된 파일럿 약속, 상담 준비 시간·입력 시간·리포트 수정 횟수·재사용 의향을 동일한 방식으로 측정 | 기능별 만족도만으로 제품 적합성 판단 |
| G3. 유료성 | 최소 1곳의 유료 PoC 또는 가격·기간·구매 주체가 명시된 조건부 도입 합의 | 무료 파일럿을 반복 매출 증거로 표현 |
| G4. 확장 | G2/G3 결과에서 반복 사용 장면과 구매 이유가 확인되고, 개인정보·운영 비용을 감당할 수 있음 | 스마트워치 연동, AI 모델 학습, 업종 확장 선행 |

## 5. 외부 심사에서 지켜야 할 표현

- "AI가 진단한다", "통증 원인을 분석한다", "부상 위험을 예측한다"고 말하지 않는다.
- 고객 수, 매출, 전환율, 임상 정확도, 특허 보유 여부는 증거가 없는 한 `[검증필요]`로 남긴다.
- `AUTO`는 안전 보증이 아니고, `BLOCK`은 의료 판정이 아니라 트레이너 검토 전 운영 보류다.
- Hugging Face는 향후 합성 데이터 기반의 재현 가능한 연구·평가 도구로만 검토한다. 실사용 회원 기록, 이미지, 건강 관련 원본 데이터는 업로드하거나 학습에 사용하지 않는다.

## 6. 의사결정 기록 형식

파일럿 회고와 투자/지원 제출물에는 아래 네 항목을 반드시 함께 남긴다.

| 항목 | 기록 질문 |
|---|---|
| 사실 | 실제로 관찰되거나 계약·로그로 확인된 것은 무엇인가? |
| 해석 | 그 사실이 고객 문제나 지불의사에 대해 의미하는 것은 무엇인가? |
| 한계 | 표본, 데이터 품질, 운영 조건의 한계는 무엇인가? |
| 다음 결정 | 유지, 수정, 중단 중 무엇을 선택하며 그 근거는 무엇인가? |

이 형식을 지키면 심사자가 원하는 냉정한 태도, 즉 주장보다 증거와 한계를 먼저 제시하는 태도를 일관되게 보여줄 수 있다.
