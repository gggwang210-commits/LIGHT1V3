> PT 센터와 트레이너를 위한 비의료 운동상담 SaaS MVP  
> Repository: `gggwang210-commits/LIGHT1V3`  
> 기준 브랜치: `Main-ONE`  
> 문서 기준일: 2026-07-10

---

## 1. 프로젝트 소개

**LIGHT ONE V3**는 PT 센터, 헬스장, 트레이너가 회원의 운동 수행 기록과 상담 정보를 구조화하고, 트레이너 검토용 상담 리포트 초안을 생성할 수 있도록 지원하는 Django 기반 SaaS MVP입니다.

회원의 운동 목표, 운동 수행도, 불편 반응, 운동자각도(RPE), 촬영 품질(QC), 트레이너 메모 등을 통합해 상담 전 확인해야 할 정보를 한 화면에서 제공합니다.

LIGHT ONE은 AI 또는 점수 계산 결과가 트레이너의 전문적 판단을 대체하지 않도록 **Human-in-the-loop** 원칙을 적용합니다.

> 본 프로젝트는 의료 서비스가 아닙니다.  
> 의료 진단, 치료, 재활 처방, 질병 예측 또는 통증 원인 판정을 제공하지 않습니다.  
> 모든 결과와 리포트는 담당 트레이너가 검토한 후 사용해야 합니다.

---

## 2. 프로젝트 목표

LIGHT ONE V3의 주요 목표는 다음과 같습니다.

- 흩어진 회원 상담·운동 기록의 구조화
- 트레이너의 상담 준비 시간 단축
- 회원별 운동 수행 흐름과 변화 기록
- 설명 가능한 상담 리포트 초안 제공
- 검토가 필요한 세션의 우선순위 분류
- PT 재등록 상담과 회원 관리 지원
- 비의료 운동상담 SaaS의 사업성 검증

현재 단계는 상용 운영 버전이 아니라, 실제 센터에서 사용성과 구매 가능성을 검증하기 위한 **파일럿 MVP**입니다.

| 기능 | 설명 |
|---|---|
| 회원 관리 | 회원별 목표, 운동 정보, 상담 기록 관리 |
| 세션 기록 | 운동 수행도, RPE, 불편 반응, 트레이너 메모 기록 |

| QS 참고 점수 | 운동 수행 관련 입력값을 조합한 내부 참고 지표 |
| JATC 참고 점수 | QS와 운동 품질, 불편 반응, 운동 강도를 조합한 참고 지표 |
| 세션 라우팅 | AUTO, REVIEW, BLOCK 상태로 검토 우선순위 분류 |

| 촬영 QC | 촬영 품질과 입력 데이터 신뢰도 확인 |
| 합성 데이터 | 실제 회원 개인정보를 사용하지 않는 데모 데이터 제공 |
| 비의료 안전 문구 | 의료 서비스로 오인되지 않도록 주요 화면에 고지 |

## 5. 서비스 처리 흐름

```text
회원 및 세션 정보 입력
        ↓
입력값 형식과 촬영 QC 확인
        ↓
QS 참고 점수 계산
        ↓
JATC 참고 점수 계산
        ↓
AUTO / REVIEW / BLOCK 분류
        ↓
상담 리포트 초안 생성
        ↓
담당 트레이너 검토
        ↓
회원 상담 자료로 활용
```

AI 또는 점수 계산 결과만으로 회원에게 리포트가 자동 전달되어서는 안 됩니다.

## 6. 라우팅 상태 정의

### AUTO

입력값과 QC 상태가 내부 기준을 충족해 일반적인 트레이너 검토 절차로 진행할 수 있는 상태입니다.

AUTO는 의료적 안전이나 운동 적합성을 보증하는 의미가 아닙니다.

### REVIEW

불편 반응, 수행 점수, 촬영 상태 또는 입력값 중 추가 확인이 필요한 항목이 있는 상태입니다.

담당 트레이너가 원본 기록과 회원 상태를 다시 확인해야 합니다.

### BLOCK

입력값 또는 QC 상태에 중대한 확인 사항이 있어 트레이너 검토 전 리포트 진행을 보류한 상태입니다.

BLOCK은 다음을 의미하지 않습니다.

- 질병 위험 판정
- 의료적 응급 상태
- 운동 금기 진단
- 치료 또는 재활 필요 판정

BLOCK은 오직 **트레이너 검토 전 진행 보류 상태**를 의미합니다.

## 7. QS·JATC 엔진

현재 참고 점수와 라우팅 관련 주요 로직은 다음 경로에서 확인할 수 있습니다.

```text
lightone_v2_django/lightone/algorithms.py
lightone_v2_django/lightone/utils/qs_calculator.py
```

대표 함수는 다음과 같습니다.

```python
calculate_qs(...)
calculate_jatc(...)
determine_routing(...)
route_session(...)
```

현재 QS와 JATC의 가중치 및 임계값은 파일럿 검증을 위한 내부 MVP 기준입니다.

따라서 다음 검증이 필요합니다.

- 트레이너 전문가 검토
- 실제 세션 데이터 기반 분포 확인
- 입력값 민감도 분석
- 라우팅 오류 사례 분석
- 센터별 운영 기준 차이 검토
- 설명 가능성과 사용자 이해도 평가

점수는 의료적 위험도나 건강 상태를 의미하지 않습니다.

## 10. 로컬 실행 방법

### 10.1 저장소 다운로드

```bash
git clone https://github.com/gggwang210-commits/LIGHT1V3.git
cd LIGHT1V3
git checkout Main-ONE
```

### 10.2 Django 프로젝트 폴더 이동

```bash
cd lightone_v2_django
```

### 10.3 가상환경 생성

#### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

PowerShell 실행 정책 오류가 발생하면 CMD를 사용합니다.

#### Windows CMD

```cmd
python -m venv .venv
.venv\Scripts\activate.bat
```

#### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 10.4 패키지 설치

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 10.5 데이터베이스 적용

```bash
python manage.py migrate
```

### 10.6 데모 데이터 생성

```bash
python manage.py seed_lightone
```

`seed_lightone` 명령은 데모 회원, 세션, 전략 데이터와 테스트 로그인 계정을 생성합니다.

### 10.7 서버 실행

```bash
python manage.py runserver
```

브라우저에서 다음 주소로 접속합니다.

```text
http://127.0.0.1:8000/lightone/
```

## 14. 비의료 서비스 경계

LIGHT ONE V3는 다음 기능을 제공하지 않습니다.

- 의료 진단
- 질병 분류
- 질환 위험도 예측
- 통증 원인 확정
- 치료 계획 수립
- 재활 처방
- 운동 금기 진단
- 의약품 또는 의료기관 추천
- AI 단독 의사결정
- 의료 전문가를 대체하는 판단

LIGHT ONE이 제공하는 것은 다음과 같습니다.

- 운동상담 기록 정리
- 운동 수행 흐름 확인
- 불편 반응 기록
- 촬영 및 입력 품질 확인
- 트레이너 검토 우선순위 지원
- 상담 리포트 초안 작성
- 회원 설명용 비의료 참고 자료

서비스 화면과 리포트에는 다음과 같은 고지가 포함되어야 합니다.

```text
본 자료는 비의료 운동상담 참고용이며 의료 진단, 치료 또는 처방 목적이 아닙니다.
모든 결과는 담당 트레이너의 검토가 필요합니다.
```

## 17. 현재 확인된 기술 리스크

현재 저장소는 파일럿 MVP 단계이며, 상용 배포 전에 코드 통합 검수가 필요합니다.

### P0 — 실행 차단 가능 항목

- `INSTALLED_APPS`에 `dashboard`가 중복 등록된 부분 정리
- `lightone/models.py`의 중복 import와 중복 모델 정의 정리
- 모델에서 참조하는 미정의 필드 확인
- `MemberSession`, `Member`, `Session`, `Indicator` 관계 재설계
- `determine_routing` 함수 호출 인자 통일
- signal과 모델 `save()`의 중복 처리 방지
- migration 재생성 및 DB 초기화 검증

### P1 — 테스트 및 자동화

- GitHub Actions 대상 브랜치를 `main`에서 `Main-ONE`으로 수정
- CI 환경에서 `python manage.py check` 실행
- migration 테스트 추가
- QS·JATC 단위 테스트 보강
- AUTO·REVIEW·BLOCK 경계값 테스트 추가
- 비의료 금지 표현 자동 검사
- 데모 계정 보안 검사

### P2 — 제품 검증

- 트레이너 입력 시간 측정
- 리포트 이해도 조사
- 라우팅 오류 사례 수집
- 상담 준비 시간 단축 여부 확인
- 재등록 상담 활용도 확인
- 센터 월 구독 지불의사 검증

### P3 — 운영 고도화

- PostgreSQL 전환
- 역할 기반 접근제어(RBAC)
- 회원 데이터 삭제 기능
- 감사 로그(Audit Log)
- API 분리
- 비동기 작업 처리
- 배포 환경 분리

## 19. 파일럿 검증 계획

권장 검증 순서는 다음과 같습니다.

1. 합성 데이터만 사용해 데모 환경을 안정화합니다.
2. 트레이너 1~2명에게 상담 리포트 이해도를 확인합니다.
3. 회원 1건 입력에 필요한 시간을 측정합니다.
4. AUTO, REVIEW, BLOCK 분류가 실제 업무 흐름에 맞는지 확인합니다.
5. 리포트가 상담 설명에 도움이 되는지 평가합니다.
6. 센터 대표에게 월 구독 가격 지불의사를 확인합니다.
7. 실제 데이터 사용 전 개인정보와 비의료 표현을 검토합니다.

### 핵심 검증 지표

- 회원 1명 입력 소요 시간
- 리포트 생성 소요 시간
- 트레이너 수정 횟수
- 리포트 이해도
- 상담 준비 시간 변화
- 재사용 의향
- 월 구독 지불의사
- 잘못된 라우팅 비율
- 개인정보 입력 오류 건수

## 20. 제품 포지셔닝

LIGHT ONE V3의 핵심 포지셔닝은 다음과 같습니다.

```text
비의료 PT 상담 리포트 SaaS
```

LIGHT ONE의 경쟁력은 단순한 체형 점수 생성이 아니라 다음 운영 흐름을 구조화하는 데 있습니다.

```text
회원 기록
→ 세션 데이터
→ 불편 반응 확인
→ 촬영 QC
→ 검토 우선순위
→ 상담 리포트
→ 트레이너 설명
→ 회원 관리
```

제품의 핵심 사용자는 일반 소비자보다 PT 센터 대표와 트레이너입니다.

## 21. 문서 관리 원칙

문서 간 내용이 충돌할 경우 다음 우선순위를 적용합니다.

1. 루트 `README.md`
2. `docs/`의 최신 기준 문서
3. Django 앱 내부 문서
4. 이전 버전 문서와 archive
5. 아이디어 및 초기 기획 자료

오래된 문서에는 LIGHT ONE V1 또는 V2 표현이 남아 있을 수 있습니다.

현재 저장소의 제품 버전 기준은 **LIGHT ONE V3**입니다.

내부 코드 경로와 Django 앱 이름은 기존 호환성 때문에 `lightone_v2_django`를 유지하고 있습니다.
