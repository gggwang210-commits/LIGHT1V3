# Privacy and security checklist

## 배포 전 필수

- [ ] 설문에 수집 목적, 수신자, 선택 입력, 비의료 범위를 표시한다.
- [ ] 이름·기관·회신 이메일·전화번호는 선택 입력으로 유지한다.
- [ ] 주민등록번호, 계정 비밀번호, 상세 의료정보 입력 금지 문구를 표시한다.
- [ ] Script Properties에만 Airtable PAT와 Slack Webhook을 저장한다.
- [ ] GitHub Actions와 로그가 요청 본문·토큰을 출력하지 않도록 한다.
- [ ] Drive 폴더와 응답 Sheet 공유 대상을 최소화한다.
- [ ] Airtable에는 기본적으로 연락처를 동기화하지 않는다.
- [ ] Slack에는 응답 ID, 역할, 처리 상태만 전송한다.
- [ ] 보유기간, 삭제 요청 창구, 백업 삭제 기준을 문서화한다. `[검증필요]`
- [ ] 개인정보 처리 위탁 및 국외 이전 여부를 실제 서비스 약관과 대조한다. `[검증필요]`

## 운영 중 확인

- [ ] 응답 처리 실패와 재시도 횟수를 주기적으로 확인한다.
- [ ] Webhook 또는 PAT 유출 의심 시 즉시 폐기·재발급한다.
- [ ] 테스트 응답과 실제 응답을 구분한다.
- [ ] 오류 메시지에 이름·전화·이메일이 포함되지 않도록 정제한다.
- [ ] 분석용 데이터는 `public-export.schema.json`을 통과한 별도 파일만 사용한다.

## 삭제 요청 처리 최소 절차

1. 요청자의 신원을 최소 정보로 확인한다.
2. `RESPONSE_ID`로 Sheet, Drive PDF, Airtable 운영 레코드를 찾는다.
3. 원본·복제본·백업의 처리 범위를 기록한다.
4. 삭제 또는 법적 보관 예외를 처리한다.
5. 완료 일시와 담당자를 감사 로그에 남긴다.
